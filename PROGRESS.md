## WebMCP security hardening — S0 contract addendum (RATIFIED 2026-08-30)

Status: **CONTAINED / RATIFIED BY THE HUMAN ON 2026-08-30.** This addendum is the approved implementation basis but does not amend frozen `docs/CONTRACTS.md` and authorizes no deployment, credential rotation, or bridge enablement. Repository deployment configuration still pins `BRIDGE_ENABLED="0"`; the latest human-recorded production evidence above also says the bridge remains disabled. The live Render environment was not changed or independently inspected in this milestone.

### Threat model and containment

- Trust no WebMCP input, graph or journal prose, worker output, artifact URL, model output, actor header, URL parameter, browser-stored value, bearer token, `Origin`, or connection count. A syntactically valid supervisor decision is untrusted data until deterministic authorization accepts it.
- Protect repository contents/history, model credentials and spend, all visitor/share/realtime/reporter capabilities, actor and approval audit accuracy, browser-agent instruction priority, and Render/SQLite/realtime availability.
- Current containment for SEC-001/SEC-002 is the disabled production bridge. It must remain disabled until the supervisor boundary, human-presence authorization, worker credential/egress isolation, and their adversarial tests pass. Any isolated development proof must use scratch data, no valuable credential, and no production capability.

### Proposed v1.6 security contract

1. **Server-derived identity and human presence (SEC-002).** Authorization derives from the authenticated route and server-held session/capability, never `x-mg-actor`; a retained header is audit-only `claimed_actor`. `state_policy` stages a pending draft. Native UI displays exact policy text, policy hash, project, session, allowed approval actions, maximum uses, and expiry; only an explicit UI confirmation mints a random grant. Approval and rejection require that project/session/action-bound grant even when the caller claims to be human. Dispatch, pause/resume, destructive confirmation, and worker-facing `brief_override` require their own visible human-presence confirmation.
2. **Replay-safe grants.** Store only hashes of grants. Bind each grant to project, server browser session, policy hash, allowed actions, creation/confirmation timestamps, expiry, and a bounded multi-use budget. Bind every consequential execution to a unique single-use nonce/idempotency key. Reject wrong project/session/action/text, denial, expiry, exhaustion, and replay before appending an event. Audit accepted events with the server-derived actor, policy text/ref, request origin, confirmation timestamp, and nonce outcome without recording raw capabilities.
3. **Deterministic supervisor authorization (SEC-001).** Supervisor output proposes actions but grants no authority. Validation receives the triggering envelope set and current reducer state, and accepts only actions enabled by an exact server capability: confirmed explicit dispatch for that node; policy-compliant automatic critical-path spawn within cap; state-valid retry/pause/resume; rebrief limited to the computed structural blast radius; or kill with an explicit server-authorized reason. Block duplicate/tracked, blocked, running, review, done, group, or tombstoned spawns. Worker instructions come from reviewed immutable execution templates plus typed canonical node parameters fetched by the bridge; the model cannot supply an authoritative worker brief.
4. **Worker and reporter isolation (SEC-001).** Worker processes default to no network and receive no `OPENAI_*`, `CODEX_*`, global reporter/admin token, or another node's reporter credential. Model authentication must sit behind a broker/credential boundary before public workers are enabled. Reporting uses a narrow local or explicitly allowlisted channel. Seed-import administration and project-bound supervisor reporting use separate credentials; project routes never fall back to a global reporter token.
5. **Scoped capability exchange (SEC-003).** Share links contain only random, single-use, short-lived codes and default to read-only. An authenticated POST exchanges and rotates a code after the client synchronously removes it from location/history. Browser sessions use `Secure; HttpOnly; SameSite=Strict` cookies on a same-origin path where possible; a documented cross-origin fallback keeps narrowly scoped access material in memory/session storage, never persistent `localStorage`. Realtime URLs contain only one-time tickets bound to project, session, origin, transport, and expiry. Hash all share/realtime/visitor credentials at rest; support expiry, revocation, and rotation; split read, mutate, dispatch, approve, export, and share scopes.
6. **Bounded, labeled WebMCP data (SEC-005).** All MissionGraph tools set `untrustedContentHint:true` while shared envelopes can contain untrusted prose. Only operations with no server or visible-page change set `readOnlyHint:true`; camera, highlight, overlay, and camera-driving review operations are not read-only. Central limits are shared by browser schemas, client/server/reporter validation, and bridge validation: identifiers 128; title 120; tag 40/20 tags; prose fields 2,000; log lines 500/20; handoff collection fields 50; plan tasks 50; split children 20; focus IDs 50; body 256 KiB; event batch 100. Tool output targets 1.5K characters and never exceeds 8 KiB; truncation is explicit and continuation is stable. Artifact URLs allow credential-free `https:` only.
7. **Abuse and history bounds (SEC-004/SEC-006).** Patch Fastify, ws, and Vitest to non-vulnerable versions. Enforce persistent or edge-backed quotas, not resettable in-process counters: clone 3/IP/hour; mutation 60/project/minute with burst cap; dispatch 3/project/day and one active explicit dispatch; realtime 2/project plus IP cap; export/history 5/project/minute. Add visitor/project TTL, storage and event caps, pagination, replay caps, connection idle/heartbeat/backpressure limits, materialized snapshots or a hard fold cap, and fail-closed WebSocket `Origin` parity with `ALLOWED_ORIGINS`.
8. **Cancellation and atomicity (SEC-007).** Check `AbortSignal` before validation, queueing, and irreversible send; propagate it through transport/history and remove canceled queued work. Consequential mutations are atomic batches. A pre-commit cancellation appends nothing; a post-commit ambiguity reconciles by idempotency status to exactly one recorded result and is never blindly retried.
9. **Browser/API defense in depth (SEC-008).** Frontend and API deploy CSP, `Referrer-Policy:no-referrer`, `Permissions-Policy:tools=(self)`, origin isolation, `nosniff`, anti-framing/form/base restrictions, HSTS where appropriate, fail-closed CORS, and matching WebSocket origin checks. No valid capability may appear in URLs, history, referrers, access/application logs, console output, or screenshots.
10. **Stable failures.** Oversized request bodies return `413`; field/schema violations return `400`; quota/concurrency exhaustion returns `429` with `Retry-After`; expired and replayed capabilities return `capability_expired` and `capability_replayed`. All failures occur before event append and never echo secrets or full untrusted input.

### Scenario preservation

- **S1 Genesis:** bounded `plan_seed` and graph edits remain atomic and conversational; ordinary non-consequential co-authoring needs no new approval ceremony.
- **S2 Flight:** one visible human confirmation can mint a short-lived, action-scoped, multi-use policy grant sized to clear the demonstrated approval set; each use still has a unique nonce. Catch-up, ranking, and read tools remain agent-callable. Real dispatch receives its own visible confirmation.
- **S3 Rewire:** the existing blast-radius preview remains, but applying a running-graph rewire additionally consumes a UI-confirmed, proposal-bound human-presence capability; deterministic authorization rebriefs only the computed affected workers.

### S2 — Server-derived identity and human-presence grants (COMPLETE 2026-08-31)

- Consequential browser-agent actions now use the dedicated `/agent-mutations` route and ignore any client-supplied actor claim. Policy creation only stages a pending server draft; it returns no public policy reference or capability. The visible native dialog renders the exact policy/action text, SHA-256 binding, project, server-issued browser session, allowed actions, use limit, and expiry before confirmation.
- Browser sessions are server-issued as a public id plus a random proof. The client keeps the proof only in module memory, the database stores only its SHA-256 hash, and every draft, confirmation, denial, and capability use verifies the project-bound session proof. Confirmed grants are random, hashed at rest, bound to project/session/kind/policy or exact action subject/expiry/use budget, and consumed transactionally with a unique nonce and the accepted event append.
- Human approval/rejection, dispatch, pause/resume, and structural mutations use visible action confirmations. Accepted consequential events record the server-derived actor plus capability reference, confirmation time, request origin, and nonce without persisting the raw grant.
